\# Task 5: Static Website Hosting with GitHub Pages



\## Objective



Build and publish a static website using HTML, CSS, Git, GitHub, and GitHub Pages.



\## Technologies Used



\- HTML5

\- CSS3

\- Git

\- GitHub

\- GitHub Pages



\## Project Files



\- `index.html` — website structure and content

\- `style.css` — responsive website styling

\- `README.md` — project documentation

\- `screenshots/` — deployment evidence



\## Deployment Steps



1\. Create the website using HTML and CSS.

2\. Commit and push the source files to GitHub.

3\. Open the repository's Settings → Pages.

4\. Select \*\*Deploy from a branch\*\*.

5\. Select the publishing branch and folder.

6\. Save and wait for GitHub Pages to publish the website.

7\. Open the live URL provided by GitHub.



\## Interview Questions



\### 1. What is GitHub Pages?



GitHub Pages is a hosting service that publishes static websites from GitHub repositories.



\### 2. Can you host dynamic applications on GitHub Pages?



GitHub Pages does not execute server-side code such as Node.js, Python, or PHP. A static frontend can call an external backend API.



\### 3. What are the limits of GitHub Pages?



It is intended for static sites and has published build, deployment, and usage limits. It is not a replacement for a general-purpose application server.



\### 4. How do you update the website?



Edit the HTML or CSS, commit and push the changes to the publishing source, and wait for GitHub Pages to redeploy the site.



\### 5. What happens when you delete the repository?



The website hosted from that repository will no longer be available through its GitHub Pages deployment.



\### 6. What is the default file that loads?



`index.html` is the standard entry point for a static website.



\### 7. Can you use a custom domain?



Yes. GitHub Pages supports custom domains with appropriate domain and DNS configuration.
